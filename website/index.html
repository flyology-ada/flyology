Systems foundations for Ada

Flyology Runtime

Flyology Runtime begins with ordinary Ada tasking. Native tasks keep their OS threads, while lightweight tasks run cooperatively on shared event loops. Around that execution model, Flyology provides synchronous task-aware I/O and bounded building blocks for supervision, ownership transfer, shared memory, and relocatable data structures.

Programming model

Native and lightweight tasks share Ada semantics.

An undesignated task stays native. Lightweight execution is explicit and captured at task creation. Both lanes remain ordinary Ada tasking.

Runtime architecture

Each part has a separate responsibility.

The poller reports readiness. The scheduler chooses a runnable fiber. The context switch preserves its stack. Existing Ada tasking machinery continues to define task behavior.

Read the architecture guide
  1. 01

    Event polling

    kqueue on Darwin or epoll plus eventfd on Linux waits for sockets, file completions, timers, and cross-thread wakes.

  2. 02

    Cooperative scheduling

    Per-group priority queues and deadline heaps select ready work. A CPU-bound lightweight task must suspend, yield, or call a fairness checkpoint.

  3. 03

    Stackful contexts

    Guarded mmap stacks and a small register swap preserve locals, exception state, Ada task identity, and synchronous control flow.

  4. 04

    Ada task semantics

    Flyology changes where a task executes, not what an Ada task means. Rendezvous, protected objects, activation, masters, abort, and task identity retain their ordinary semantics.

Included building blocks

Ordinary calls around explicit boundaries.

Flyology Runtime includes task-aware I/O, execution-group control, bounded ownership transfer, structured supervision, shared-memory mappings, and relocatable data structures. Capacity, ownership, recovery, and blocking remain explicit.

Boundaries

Experimental, with documented constraints.

Flyology does not claim hard real-time behavior, preemptive lightweight scheduling, or universal compiler portability. Runtime preparation fails closed when a host and compiler release are not in the verified patch matrix.

Review current constraints
ConcernContract
CompatibilityUndesignated tasks remain native; event machinery starts lazily.
FairnessScheduling within a group is cooperative, with explicit yield points.
Foreign callsBlocking foreign work belongs on a native task or a dedicated group.
Compiler supportOnly exact, versioned compiler patch families are accepted.

The name

A study of flight, revisited.

In 1828, Ada Lovelace studied bird anatomy, experimented with materials for wings, and planned a book she called Flyology. This project borrows that name for another study in making familiar forms move differently.
