# Linux Rust bridge matrix

This portability spike runs every integrated Ada/Rust bridge spike in the
repository's Linux Docker environment. It reuses the
standard Flyology Linux image so the Ada side stays on the supported patched
GNAT 16.2 and GPRbuild 26.0.1 toolchain, then adds pinned Rust 1.97.1.

Run from any directory:

```sh
./spikes/flyology-rust/linux-aarch64/run.sh
```

The default target is Linux/x86-64. The runner builds two local images, runs
the suite, and removes both images even after failure. Set
`FLYOLOGY_KEEP_RUST_LINUX_IMAGES=1` to retain them. An explicit
`FLYOLOGY_RUST_LINUX_ARCH=arm64` selects Linux/AArch64 and currently exercises
the fail-closed GPR configuration probe described below.

The container prints exact kernel, distribution, Rust, Alire, GNAT, and
GPRbuild versions before running:

1. ABI layout, ownership, thread-local state, and panic translation with
   static and dynamic Rust libraries in debug and release profiles;
2. the Ada-hosted Tokio bridge stress pass on both task lanes;
3. Rust-hosted Ada initialization, foreign-thread registration, native and
   lightweight child creation, and finalization;
4. direct future polling, wake-before-arm, delayed wake, cancellation, and
   isolated native/lightweight panic probes;
5. the explicit static/dynamic unwind matrix on both Ada task lanes.

Cargo is offline during the test run. The image build is the only stage that
fetches the Tokio version pinned by the existing `Cargo.lock`.

## Evidence from 2026-08-31

The clean Linux/x86-64 run used a Git-exported source tree copied into fresh
Docker images, with no bind mount or reused worktree output. It used Ubuntu
24.04.4, Flyology's `gnat_flyology_native=16.2.0-patchset.1.1.0`, Alire
`gprbuild=26.0.1`, Rust/Cargo 1.97.1, and Tokio 1.53.1. The GPRbuild binary
identifies itself as `GPRBUILD 26.0.0 (2026-04-15)`.

The supported link probe created `libFlyology.a` and its executable. The ABI
matrix passed static and dynamic debug/release linkage and Rust panic
translation. The Ada-hosted Tokio stress passed shared wakes, bounded slot
reuse, cancellation races, shutdown, and same-group progress. Rust-hosted Ada
passed partition lifecycle, registered foreign-thread entry, native and
lightweight child tasks, and Rust panic containment using the documented
Linux/x86-64 non-PIE final-link policy. Direct future polling, wake and
cancellation cases passed, as did the native/lightweight unwind matrix.

The same clean control on Linux/AArch64 isolated a toolchain configuration
failure before the bridge cases. GPRbuild compiled and bound a one-file Ada
main, returned status zero, but emitted no link action or executable. The
custom GNAT configuration generated by GPRconfig omitted the object-lister and
archive-builder/indexer fields. Stock `gnat_native=16.1.0` supplied those
fields and linked; restoring only those fields to the custom configuration also
restored linking. The custom compiler and `gnatlink` worked when invoked
directly.

Both the working x86-64 and failing AArch64 GPRbuild packages lack a separate
`gprlink` executable, so that inventory item is not causal. The observed
boundary is the AArch64 custom GNAT target/configuration metadata, not a
general GPRbuild or Ada/Rust bridge failure. The AArch64 probe remains
fail-closed until that toolchain metadata is repaired. A passing complete run
ends with `PASS Linux Rust bridge spike matrix`.
